## 2. 头部与 `info` 记录

【确证】`info` 记录 = 名字 `"info"` + `{u32 payload_off, u32 payload_size}`，payload 是 0x7C 字节的**字体元数据**（二改/官方内容逐字节相同，只是被前移）：

```
01 01 00 "ICON_NEW-UCS-CNS"        ← 字体名
02 01 00 "Standard\Unicode\UCS-CNS" ← 基准字符集
03 01 00 "0100"                     ← 版本
04/05/06/07/08 …                    ← 度量/标志（含 0xC8, 0xFFA6, 0x32 等）
01 02 00 "202212201341"             ← 构建时间 2022-12-20 13:41
```
> 该 payload 只随整包平移（官方 `0xA2FE5` → 二改 `0xA31C2`，+0x1DD），说明二改在 info 之前**插入/扩展了字形数据**，不是改字体配置。

头部 `+0x1C..+0x3F` 的 28 字节两版**完全相同**：
`26 f7 4c 00 00 00 ed dc 03 00 4e 00 00 00 ed dc 03 00 51 00 00 00 ed dc 03 00 04 00 00 01 3e 32 0a 00 00 00`
（【推测】小型描述/度量记录，未影响本次结论。）

## 3. 语言块内的 3 类记录

### 3.1 8 字节消息记录（UI 文本/标签的核心）
```
struct msg8 { u32 text_off; u16 style; u16 count; }     // 8 B
```
* `style` 实测取值：`0x0050, 0x012C, 0x0154, 0x0168, 0x0190, 0x01B8, 0x0208, 0x021C, 0x0244`
* `count` 实测 1..3（多行/复合文本的行数）。
* `text_off` 是 24 位量级的池内偏移；在官方 build 中约有 3/4 的记录 `B + text_off`（B=`0x1DA0274`）能解出**可读的本地化文本**，因此它是「文本池相对偏移」，但**池本身是全局排布**的（本块记录可指向别的块的字符串），不要用它反推语言。
* 典型位置：每块 `+0x2900..+0x2A00`（一大片菜单消息表），以及 `+0x42xx`、`+0xB6xx`、`+0x12Fxx`、`+0x150xx` 等处的零散表。

### 3.2 12 字节布局条目（图标/热区/描述行）
```
struct entry12 { u32 ref; u16 w; u16 h; u32 flags; }   // 12 B
```
* `w == h == 100` 占绝对多数（100×100 的显示格）。
* `ref` 是**共享引用值**（全包范围内 `0x8B2EC8..0x8DFF40`；官方 `0x8B2EC8..0x8D1694`），同一 `ref` 在 35 个语言块里重复出现 ⇒ 与「图标/预渲染位图」一类**共享资源**有关，**不是**语言文本。
* `flags` 只观察到 `0` 和 `2`，`2` 只出现在 RTL 语言块（希伯来等）⇒ **flags = 排版标志（RTL 等），不是 family id / 子项计数**。
* 12B 条目在块里成组出现，组间夹文本；**没有**「父条目指针」或「子项数」字段。

### 3.3 文本（UTF-16LE，PUA 前缀 = 内嵌图标/子串引用）
* 普通标签：`"MONOCHROME"`、`"REALA ACE"`、`"NOSTALGIC Neg."`…
* 复合标签：`'\uf2fa\uf2ef+G FILTER'`、`'\uf1b5MONOCHROME+G FILTER'`…（`\uf0xx..\uf4xx` = 图标字形 / 子串引用，非普通字符）
* **PROVIA/Velvia/ASTIA 没有拉丁字符串**：它们用 logotype PUA 字形（`\uf06a\uf06f/STANDARD` 等）。

## 5. 右列 +R/+Ye/+G 的数据来源：为什么不在 FDL

**现象（用户实测）**：高亮 REALA ACE → 右侧出现 +R/+Ye/+G 一列；REALA 出图彩色正常；MONOCHROME 从左列消失。

**FDL 侧证据（全部为否定）**：
1. 【确证】12B 条目字段只有 `{ref, 100, 100, flags}`；`flags` 的 0/2 已定位为 RTL 排版标志。**没有** family/parent/子项计数字段。
2. 【确证】在 FDL 包范围（`0x1DA0274..0x2720274`）内扫描 `u8/u16` 的 `[8,9,10,11]`、`[4,8,9,10,11]`、`[19,20,21,22]`、`[18,19,20,21,22]`，**官方与二改均 0 命中**（`tools/_fdl_scratch23.py` 已做，临时脚本已删；可复现）。
3. 【强】用户清空 FDL 里的 B&W 滤镜标签（3 语言 × 3 种）→ **界面无任何变化** ⇒ 右列不渲染这些 FDL 字符串。
4. 【确证】二改的 26 处/块 FDL 差异里没有一处新增/删除「4 个变体条目」（§4.5），因此右列 4 项不可能是二改在 FDL 里塞进去的。

**⇒ 右列机制**：UI 代码按「家族枚举」展开连续变体枚举——B&W 家族 enum 4 → 变体 enum 8,9,10,11（NON/R/Ye/G）；ACROS 家族 enum 18 → 19,20,21,22（`UI_FILM_SIM_*` 注册表 sec1 `0x6D35F8`，23 项，index=枚举值）。二改把 REALA 挂在 enum 4 上（出图参数也走 enum 4，所以彩色正常），UI 仍按 B&W 家族展开 ⇒ 右列自然出现。**这条链路不在 FDL 数据里。**

## 6. 补丁方案

### 6.1 方案 A：只改 FDL（**达不到目标**，仅记录能改到什么）

| 目标 | 精确改动 | 改前 → 改后 | 效果/风险 |
|---|---|---|---|
| 隐藏 REALA 名称 | 每块 `+0x21B4` 首字符置 0 | `52 00`(`R`) → `00 00` | 名称变空；35 块都要改；**不影响右列** |
| 隐藏 NOSTALGIC 名称 | 每块 `+0x2174` 首字符置 0 | `4E 00`(`N`) → `00 00` | 同上 |
| 隐藏 B&W 滤镜标签 | blk0 `0x1EB9548/574/5A0` 首字符置 0（每语言块另有自己的一组，见 `film` 命令） | `4D 00`(`M`) → `00 00` | **已验证：无效果**（不在右列渲染路径） |
| 让 4 个变体"合并" | —— | —— | **FDL 内没有 4 个变体条目可改**，无法给出字节 |

> 35 个块的 `+0x2174/+0x21B4` 地址 = `0x1E9E000 + k*0x40000 + {0x2174,0x21B4}`，k=0..34。
> 结论：**FDL 数据层能改到的极限 = 文字/图标/描述**；不能改变条目数量、不能改变家族归属，因此不能隐藏右列。

### 6.2 方案 B：真正的数据层补丁（在 SETP/UI 展示层，**未定位**）

按优先级：

1. **SETP 选项/展示表（首选）**：`UI_SETP_FILM_SIM = 1070`。在 sec1 的 UI 资源区（注册表 `0x6C8150..0x6D8AA0`、胶片模拟枚举名表 `0x6D35F8` 附近）找 1070 的**选项描述符**；若选项带 `parent/group` 字段：
   - 把 enum **9/10/11**（B&W R/Ye/G）的 parent 从 `4` 改为无效值（如 0xFF/0xFFFF），保留 enum 8（NON）→ REALA 下右列只剩 NON；
   - 或把 B&W 家族的「变体个数」字段 `4 → 1`。
   - 风险：**不要碰枚举值本身/参数表/EXIF**；只改展示层。ACROS 家族（18/19..22）必须保持不动——若表结构是共享的，需确认改动只落在 enum 4 的记录上。
2. **sec0 的 19 项布局/导航表（只能改顺序，不能隐藏）**：`0x65e2d0`(u16,19) / `0x65eca8`(u16,19) / `0x65f0bc`(u8,19)，内容为 `0x10,0x11,0x12,0x00,0x08,0x07,0x09,0x06,0x0a,0x05,0x0b,0x04,0x0c,0x03,0x0d,0x02,0x0e,0x01,0x0f`，是 2/3 列网格的**走位顺序**（note 11 §7.1）。改它只能改顺序，不能减少右列项，**不满足需求**。
3. **sec0 UI 代码（若 1 无效则只能走代码）**：找按 enum 4/18 分支展开变体的函数（`MODE_FSIM_*` 名表 sec0 `0x407934`、`MODE_FSIM_NUM` 是锚点，反汇编找 `for(i=…; i<…; i++)`）。若是硬编码区间 `8..11`，则**数据层无法实现**，必须改代码；风险最高（ACROS/RAW 同源时易串档）。

### 6.3 风险清单

| 风险 | 说明 |
|---|---|
| ACROS 受影响 | 变体机制（family→连续枚举）MONO(4→8..11) 与 ACROS(18→19..22) 共用；若在**公共代码**里改，ACROS 的滤镜子项也会消失。数据层补丁应只改 enum 4 的展示记录。 |
| RAW 开发菜单 | 使用**独立**枚举表 `UI_RAW_DEV_FILM_SIM_*`（sec1 `0x6D6430`，18 项），与拍摄枚举是两套；只改拍摄展示层不影响 RAW 菜单/出图。 |
| 出图/EXIF | 只要不动枚举值、参数映射与渲染代码，REALA 仍按 enum 4 出图、EXIF FilmMode 不变。**绝对不要改 enum 表**（note 11 已证会串参数/包围曝光）。 |
| 文本层改动 | 改 FDL 文字只影响显示；但如果把标签清空用于"隐藏"，会留下空白/图标条目（用户已见）——不可取。 |
| 位置漂移 | 每语言块的文本区长度不同，`+0x274/+0x1274/+0x2xxx` 之后的地址因语言而异；补丁必须**按块重新定位**，不能只复制 blk0 的偏移。 |

## 7. 不确定 / 待验证

* 【推测】`+0x1274` 的「4:3/5:4/65:24」组：语义与用途未证实（画幅比例最像；为何被二改写入未知，可能是移植残留）。
* 12B 条目 `ref` 的坐标基准未最终确定：它是**跨语言共享**的资源引用（同值在 35 块重复），指向某个图标/预渲染资源池；`B+ref` 会落到别的语言块的文本区，说明 ref 不是普通 bundle 文本偏移。**不影响本结论**（无论 ref 指图标还是文本，它都没有分组/计数字段）。
* 8B 消息记录 `text_off` 的池基址未完全确定（部分记录 `B+off` 可解出可读文本，部分不可）；右列与左列标签的最终索引链尚未跟踪到具体 UI 表——这正是方案 B 要补的部分。
* 二改 FDL 数据「来自 GFX/更新固件移植」是**推测**（依据：新增 GFX 画幅比例组、全新 PUA 字形、逐语言描述文本）。

## 8. 复现

```
python tools/fdl_bundle.py report          # → out/fdl_bundle_report.txt（含全部 35 块、
                                           #   每块标签、mod 新区、patchmap、blk0/blk1 明细）
python tools/fdl_bundle.py header          # 8 个包 + info 记录
python tools/fdl_bundle.py blocks          # 35 个语言块
python tools/fdl_bundle.py film            # 每块 B&W/ACROS 标签 + mod 新区 + REALA/NOSTALGIC 文本
python tools/fdl_bundle.py labels --block 0
python tools/fdl_bundle.py entries --block 0
python tools/fdl_bundle.py patchmap --block 0   # 官方 vs 二改差异
```

只读保证：脚本仅 `open(..., "rb")` 两个 `decoded.bin`，不写 `.DAT`、不写镜像；产物只有 `out/fdl_bundle_report.txt` 与 stdout。
