## 0. 结论摘要

| # | 结论 | 强度 |
|---|---|---|
| 1 | 你看到的 `+R/+Y/+G/+Ye` 不是"文本"，而是**胶片模拟枚举里的 BW 滤镜变体值**：`UI_FILM_SIM_BW_FILTER_NON/_R/_Y/_G` = **enum 8/9/10/11**（`+Ye` 的标签是 `MONOCHROME+Ye FILTER`）。ACROS 家族同理 = enum 19/20/21/22。 | 确证 |
| 2 | 这些子选项**不是独立列表**，而是"B&W 家族"的成员；UI 在选中 B&W 家族条目时把它作为子项/右侧列展开（X-T4 胶片模拟选择界面）。 | 强 |
| 3 | **REALA ACE 被植入在 B&W 家族槽位上**（你说的"覆盖了 BW"），所以继承了这套子选项。二改并没有新增枚举值（23 项枚举表与官方逐字节相同）。 | 强 |
| 4 | 二改的植入方式已定位：**每个语言块有 7 处小补丁**（见 §2），把 **原本是 `0xFF` 的空槽位**填上新增文本，并**改写该语言块的消息记录表**（count / 文本偏移）。 | 确证 |
| 5 | 因此"移除子选项"的正确做法是：让 **B&W 家族不再有变体成员**，或让 UI 对 REALA ACE 不显示滤镜列 —— 需要定位 UI 的"家族/变体"逻辑，**目前未定位**（与菜单顺序表同源）。 | 未定位 |
| 6 | 已生成一个**界面行为实验固件** `out/test_remove_bwfilter.DAT`：把 9 处 BW 滤镜标签清空（3 语言池 × 3 种），用于验证"空标签是否会被 UI 跳过"。校验和已重算。 | 已产出 |

## 1. 子选项到底是什么（父子对应的枚举值）

`sec1` 的 `UI_FILM_SIM_*` 枚举名表（注册表 `{name_ptr,index}`，**index = 枚举值**）里：

| enum | 名字 | 含义 |
|---|---|---|
| 4 | `UI_FILM_SIM_BW` | MONOCHROME（**REALA ACE 疑似占用此槽**） |
| 7 | `UI_FILM_SIM_BW_FILTER` | B&W 滤镜设置项 |
| 8 | `UI_FILM_SIM_BW_FILTER_NON` | 无滤镜 |
| 9 | `UI_FILM_SIM_BW_FILTER_R` | **+R** |
| 10 | `UI_FILM_SIM_BW_FILTER_Y` | **+Ye** |
| 11 | `UI_FILM_SIM_BW_FILTER_G` | **+G** |
| 18 | `UI_FILM_SIM_ACROS_FILTER` | ACROS 滤镜设置项 |
| 19..22 | `ACROS_FILTER_NON/_R/_Y/_G` | ACROS 的同类变体 |

对应的**显示标签**（UTF-16，位于 FDL Font 文本池，3 个语言池各一份）：

```
MONOCHROME+G FILTER   0x1EB954A, 0x1EC86E4, 0x1ECDD30
MONOCHROME+R FILTER   0x1EB9576, 0x1EC8710, 0x1ECDD58
MONOCHROME+Ye FILTER  0x1EB95A2, 0x1EC8754, 0x1ECDD80
```

另有 `FILM_SIM_MONO` 设置项（SETP id **1072**，即界面上的黑白滤镜设置）与电影版 1075。

## 2. 二改是怎么把 REALA ACE 塞进去的（新证据）

对「官方 v2.12 vs 当前二改」的**未压缩文本区**（decoded `0x1DA0000..0x2721000`）做逐字节对比，发现改动呈**严格的每 0x40000 一块、每块 7 处**的规律（块 = 一个语言/界面分块）：

| 块内相对偏移 | 长度 | 作用（推断） |
|---|---|---|
| `+0xE274` | 244–548 B | **新增文本**（官方此处全 `0xFF`，二改填入文本） |
| `+0xF274` | 88 B | 新文本的指针/索引表 |
| `+0x2174` | 30 B | `NOSTALGIC Neg.` 文本 |
| `+0x21B4` | 20 B | `REALA ACE` 文本 |
| `+0x0966` | 5 B | 消息记录表条目（**count 2→3**，偏移改指新文本） |
| `+0x0988` | 11 B | 消息记录表条目（1→1、2→3，偏移改指） |
| `+0x2290` | 19 B | 另一处消息记录/指针 |

实例（块 `0x1E9E000`，官方 → 二改）：

```
0x1EA0966: 02 00 4C1D8B00 9001   →   03 00 48E18D00 9001     (count 2→3, 指向新文本)
0x1EA0986: 01 00 AC1D8B00 9001   →   01 00 80E18D00 9001
0x1EA098E: 02 00 B81D8B00 0208   →   03 00 8CE08D00 0208
0x1EA01B4: FF…                   →   "R E A L A   A C E"    (UTF-16)
0x1EA0174: FF…                   →   "N O S T A L G I C   N e g ."
```

解读：二改把 **官方预留的空槽位（`0xFF`）**当作"新消息"仓库，修改每个语言块的消息记录表，让某些菜单项的文本指向新内容。这正是"移植两个新胶片模拟"的实现方式——**没有动枚举表、也没有新增枚举值**。

> 推论：REALA ACE 之所以继承 BW 的滤镜，是因为它被挂到了 **BW 家族**（enum 4 及 8..11）对应的记录上；UI 按"家族"展开子选项，于是 BW 的 4 个滤镜被一起带出来。

## 3. 三种"移除"方案

| 方案 | 做法 | 可行性 / 风险 |
|---|---|---|
| **A. 清空 BW 滤镜的显示标签**（实验） | 把上面 9 处标签文本首字符置 0（空串） | **低风险、可立即试**：如果 UI 对空标签会跳过 → 直接达成；若显示空白条目 → 说明需要代码级补丁。已生成实验固件（见 §4） |
| **B. 让 BW 家族不再有变体成员** | 改 UI 的"家族→变体"表（把 BW 的变体数改成 0/1） | 正解，但**该表尚未定位**（与菜单顺序表同源，见 notes/11 §5） |
| **C. 把 REALA ACE 改挂到非 B&W 家族** | 改被改写的那几条消息记录/枚举映射，让 REALA ACE 指向 enum 4 以外的槽 | 有风险：**出图参数通常跟随枚举值**，换家族可能让 REALA ACE 变成别的胶片模拟 |

> 不建议：改 enum 8..11 的名字表/枚举名（那只是调试名，不影响 UI）；改标签成重复文本（会导致界面上出现 4 个同名 REALA ACE）。

## 7. 实验反馈与机制更正（用户实测：清空标签 → 界面无变化）

**实测结论：清空 `MONOCHROME+R/+Ye/+G` 文本标签，界面完全不变** ⇒ 这些字符串不是该界面的渲染源。

### 7.1 机制更正：界面是「字形图标 + 文本」，子选项是独立枚举值

* FDL Font 包是**字体资源**：里面有海量 12 字节字形记录 `{u32 bitmap_off, u16 w≈100, u16 h≈100, u32 pad}`，按字形 id 排列。
* 胶片模拟的"名字/图标"是 **PUA 字形**（如 `\uf06a\uf06f/STANDARD` = PROVIA），`+R/+Ye/+G` 这类子选项的标签也是"PUA 图标 + 本地化文本"（如 `\uf1b5MONOCHROME+G FILTER`、日文 `\uf1b5モノクロ+Gフィルター`）。
* 子选项本身是**枚举值 8..11（BW）/ 19..22（ACROS）**，由 UI 的"家族/两列"逻辑枚举出来；清文本不会移除条目，只会让文字变空（图标还在）。

### 7.2 二改的准确手法（新证据）

逐字节 diff 未压缩文本区，每 0x40000 块（每语言）都有：

| 改动 | 内容 |
|---|---|
| **字形位图替换**（2 处/块） | 例：`0x1EA96A0` 记录里的 icon 偏移 `0x8B9358 → 0x8DFF40`（100×100），即把某个胶片模拟图标**换成 REALA ACE 色块**；`0x1EA96EC` 是第二处（对应 NOSTALGIC Neg.） |
| **文本新增** | 官方 `0xFF` 空槽填入 `REALA ACE` / `NOSTALGIC Neg.`（每语言 2 条） |
| **标签记录重指** | `+0x0966 / +0x0988 / +0x2290` 处记录改指新文本 |
| 枚举表 | **完全没动**（23 项 `UI_FILM_SIM_*` 与官方一致） |

⇒ 二改是"**换皮（图标+文本）**"，把 BW / 另一黑白位置显示成 REALA ACE / NOSTALGIC Neg.，但底层仍是黑白家族 → **继承了黑白滤镜的两列子选项**。

### 7.3 已排除的数据层假设（更新）

* 23 项"家族/base"数组（BW 组=4,7..11；ACROS 组=18..22）→ 全库扫描无命中
* 23 字节"是否 mono"flag 数组、u32 家族 bitmask（0x7CF090/0xF90/0x40010 等）→ 命中均为无关表
* SETP 1070/1072 的"值列表"记录（id + 小整数数组）→ 无命中
* PUA 标签 id 分组表 → 只找到字体/字形相关表
* 13 项菜单顺序数组（上轮已排除）

⇒ **结论：右列的"家族"判定不在已知数据表里，必须在 UI 代码里**（或尚未定位的资源结构）。下一阶段：反汇编 sec0/sec1 中构建胶片模拟选择界面的函数（锚点：SETP 1070/1072、`UI_MENU_KIND_*FSIM*`、字形表索引）。
