## 1. 文本池在哪里

整个界面/字体资源是一个 `FDL Font` 资源包：

```
decoded 0x1DA0274  "FDL Font\0"                      ← 包魔数
          +0x1C    u32 = 0x004CF726                   ← 未知（疑包长度/版本）
          +0x40    "info" + u32 offset + u32 size     ← 命名记录（示例 1 条）
          ...      位图字体区（{u32 bitmap_off, u16 w=100, u16 h=100} 表）
          ...      各语言文本池（每个语种一块，UTF-16LE 字符串池）
decoded 0x2720274  "FDL Font"                         ← 下一个同类资源包（共 8 个）
```

**已定位的语言文本池**（同一包内，顺序排列）：

| 语言 | 池起始（decoded） | 池结束（实测/估算） | 大小 |
|---|---|---|---|
| 日本語（kana 主导） | `0x1E73274` | `0x1E84xxx` | ~72 KB |
| **简体中文（本指南目标）** | **`0x1FB3244`** | **`0x1FC05F8`** | **54,196 B** |
| 繁體中文 | `0x20B3274`（与简中同布局） | `0x20C05F8`（同构） | ~54 KB |
| 한국어 | `0x202xxxx` | — | ~96 KB |
| ไทย | `0x2073xxx` | — | ~110 KB |
| Русский | `0x20F3xxx` | — | ~119 KB |
| العربية | `0x23F3xxx` | — | ~110 KB |

> 简体中文池的头尾都紧邻 `0xFF` 擦除填充：前面是字体位图表，后面从 `0x1FC05FA` 起是 `0xFF`，因此**池边界确定无歧义**。

## 2. 简体中文池的内部结构

### 2.1 记录格式

```
[UTF-16LE 字符串][0x0000 结尾][0x0000 填充至 2/4 字节对齐]  [下一条] ...
```

* 没有逐条的 length 字段（读取方以 `0x0000` 判定结尾），所以**缩短字符串不会破坏后续记录**；
* 每条记录的「可写空间」= 本条起点到**下一条起点**的距离，记为 **slot**（见 `out/ui_sc_strings.tsv` 的 `slot_bytes` 列）；
* slot 总是 ≥ 原字节数 + 2（至少留 2 字节 NUL）；常见 slot 为 4/8/12/16/20…（4 的倍数，个别 2 字节对齐）。

实例（`0x1FB3244` 起）：

```
01FB3240  00 00 00 00                          ← 填充/前一条尾部
01FB3244  EA 81 A8 52 F9 5B 26 71 21 6A 0F 5F  ← 自 动 对 焦 模 式
01FB3250  00 00 00 00                          ← NUL + 2 字节对齐填充
01FB3254  20 4F 1F 61 68 56 05 6E 01 6D 00 00  ← 传感器清洁 + NUL   (slot=12)
01FB3260  FE F1 20 4F 1F 61 68 56 05 6E 01 6D 00 00 00 00          (slot=16)
```

### 2.2 统计

| 项目 | 值 |
|---|---|
| 池范围 | `0x1FB3244..0x1FC05F8`（54,196 B） |
| 记录总数 | 4,041 |
| 含汉字文本 | **3,160** 条（其中 ≥2 字的 2,833 条） |
| 纯 ASCII 记录 | 501 条（`OFF`×18、`ON`×12、`-3`×12、`XLR`×6 …） |
| 单字形引用（PUA） | 216 条（`\uE120`、`\uF719`… 用于在文本中插入图标） |
| 单字/符号 | 164 条（`关`×161、`开`×119、`强`/`弱`×12 …） |
| 汉字总数 | 12,839 |
| 不同字符数 | **1,133**（见 `out/ui_sc_charset.txt`，含每字频次） |

### 2.3 内容样例（按池内顺序，前 12 条 / 后 6 条）

```
0x1FB3244  自动对焦模式       0x1FB4CAC  中性色调，最适合编辑图像。
0x1FB3254  传感器清洁         0x1FB4CFC  XLR麦克风适配器(2通道)+相机(2通道)
0x1FB3260  传感器清洁         0x1FB4D44  ISO拨盘操作
0x1FB3298  日期时间未设定     0x1FB4D80  59.94P/50P将自动
0x1FB32B4  信息显示           0x1FB4D9C  变更为29.97P/25P
0x1FB32C4  自定义             0x1FB4E10  数码（DIS）应用图像稳定器
0x1FB32D4  无信息显示         0x1FB4E4C  无法与全高清高速录制一同使用
0x1FB32E4  有信息显示         ...
0x1FB32F4  详细信息           0x1FC05B4  关闭相机。
0x1FB3300  收藏               0x1FC05C0  卡保护
0x1FB3320  格式化             0x1FC05D8  切换到卡槽 1
0x1FB332C  删除所有数据       0x1FC05E8  切换到卡槽 2
```

### 2.4 三个必须知道的特性

1. **文本是「预换行片段」**：长句被固件在编译期切成多行，每个片段是独立记录。例如
   `0x1FB4D70 对于录制，` → `0x1FB4D80 59.94P/50P将自动` → `0x1FB4D9C 变更为29.97P/25P`。
   ⇒ 替换时请**保持与原片段相近的显示宽度**（汉字/全角=2 列，ASCII=1 列），否则菜单可能溢出或截断。
2. **特殊 token 混在文本里**：单字 PUA（`U+E1xx`、`U+F0xx–U+F7xx`）是内嵌图标/字形占位；格式串里有 `IN %d` 之类的片段（如 `自定IN 4`）。这些字符**不要删除**，否则图标消失或排版错乱。
3. **全角/半角标点**：中文文本用的是全角标点（`，` `。` `（）`）和 `U+0020` 空格混排；替换文本请沿用原文标点风格。

## 3. 修改方法

### 3.1 允许的修改（安全）

| 情形 | 是否安全 | 说明 |
|---|---|---|
| 同长度替换（如 `传感器清洁`→`传感器除尘`） | ✅ | 推荐，最稳 |
| 缩短（如 `删除所有数据`→`删除数据`） | ✅ | 剩余字节写 0x0000 即可 |
| 在 slot 内加长（如 `信息显示`→`信息显示(改)`，slot=12 可放 5 汉字+1 ASCII） | ✅ | 只能用到 slot−2 字节 |
| 超出 slot 长度 | ❌ | 会挤掉下一条记录/破坏偏移，**不要做**（除非重排整池并同步所有引用，风险极高） |

**每条的可用上限**见 `out/ui_sc_strings.tsv` 的 `slot_bytes` 列：可用字节 = slot − 2，最多字符数（纯汉字）= (slot−2)/2。

### 3.2 必须同步的校验和

界文本区位于**主载荷（main body）**内（载荷偏移 `0x1FB2FD0` 起），主载荷由头部 `0x20C` 的校验和保护：

```
checksum = 0xFFFFFFFF − ( Σ 逻辑载荷字节[0 : 0x2FC0020] )   (mod 2³²)
```

尾部还有 6 个 region 校验和（R0..R5，位于载荷 `0x2FC0020` 之后），**改文本不影响它们**。
如果不同步 `0x20C`，相机更新时会因校验失败而拒绝该 `.DAT`。

### 3.3 工具

```powershell
$py = "C:\Users\90732\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe"

# 1) 查看/导出（已生成，可重跑）
& $py tools\ui_extract_sc.py        # -> out/ui_sc_strings.tsv / .txt  (3,160 条含汉字)
& $py tools\ui_sc_inventory.py      # -> out/ui_sc_pool_all.tsv       (4,041 条全类型)
& $py tools\ui_charset.py           # -> out/ui_sc_charset.txt        (1,133 字符+频次)
& $py tools\ui_pool_ranges.py       # 打印各语种池范围

# 2) 打补丁（只读原文件，产出新文件）
& $py tools\ui_patch.py --list                       # 列前 20 条
& $py tools\ui_patch.py --demo out\demo_patched.DAT  # 样例：改 3 条并验证
& $py tools\ui_patch.py --patch mypatch.json out\FWUP0024.DAT
```

`mypatch.json` 格式：

```json
[
  {"offset":"0x1FB3254", "old":"传感器清洁", "new":"传感器除尘"},
  {"offset":"0x1FB32B4", "old":"信息显示",   "new":"信息显示改"},
  {"offset":"0x1FB332C", "old":"删除所有数据","new":"删除数据"}
]
```

工具会：校验新旧文本 → 检查 slot 是否够 → 写入 → 补 NUL → **重算 0x20C** → 取反写回 → 生成文件后**再读回验证**（打印 checksum 对比与改后文本）。

### 3.4 手工修改（不用工具时）

1. 用 `out/decoded.bin`（逻辑镜像）= `file[0:0x274] + ~file[0x274:]`；
2. 在 `decoded` 偏移处把新文本写成 UTF-16LE + `00 00`，剩余 slot 补 `00`；
3. 重算主校验和：`ck = 0xFFFFFFFF − (Σ decoded[0x274 : 0x274+0x2FC0020]) & 0xFFFFFFFF`（注意：校验和覆盖的是**逻辑载荷**，即从解码镜像 `0x274` 起、长度 `0x2FC0020` 的那段），写入 `file[0x20C..0x20F]`（LE）；
4. 全文件写回：`out[0:0x274] = decoded[0:0x274]`，`out[0x274:] = ~decoded[0x274:]`。

## 5. 字形（字体）风险 —— 改字前必看

文本和字体是**分开存储**的：字体是本资源包里 `0x1DA0274+0x3000` 起的**位图表**（每条 `{u32 bitmap_off, u16 w=100, u16 h=100}`），文本池只存字符串。因此：

* **只能使用「池内已出现过的字符」**，否则很可能显示为空白/方框（固件不会动态生成字形）。
* 已把池内出现过的 **1,133 个不同字符**导出到 `out/ui_sc_charset.txt`（含频次、码位）。建议改字前先查该表。
* 若必须用新字（例如某个新术语），理论上可以：
  1. 找到该字符在当前字体位图表中的条目（需要先把「字符 → 字形索引」映射解出来，**尚未解**）；
  2. 用另一个已存在字形的位图替换它（字形尺寸 100×100 级，需要重算该字形的压缩/存放格式）。
  ⇒ 属于第二阶段工作，**目前不建议**。

## 6. 上机与回退

1. 修改产物是**完整 `.DAT`**（尺寸不变、校验和正确），可直接按官方流程放 SD 卡根目录、相机内执行更新（流程见 `03-prior-art.md`）。
2. **务必保留**：① 原始 `FWUP0024.DAT`；② 官方 v2.12 原件（已在 `out/official/FWUP0024.DAT`）。
3. 建议先只改 1–3 条、刷机确认显示正常，再做批量替换。
4. 相机拒绝更新时优先怀疑：校验和未同步、文本超出 slot、文件被截断/填充尺寸改变（本工具不会改变文件尺寸）。
