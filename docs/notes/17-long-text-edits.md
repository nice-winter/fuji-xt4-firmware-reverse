## 1. 文本池的确切边界

```
decoded 0x1FB3244  第一条记录（自动对焦模式）
decoded 0x1FC05F8  最后一条记录（切换到卡槽 2）结束
decoded 0x1FC05FA  00 00（尾部对齐填充）
decoded 0x1FC05FC  FF FF ... 填充，直到 0x1FDE000（下一个语言块起点 0x1FDE274）
```

* 记录 = UTF-16LE 文本 + `0x0000` 结束符；下一条按 4 字节（个别 2 字节）对齐。
* 池结束标记是**第一个偶数偏移上的 `0xFFFF`**（不会被合法文本命中）。
* 语言块网格：`0x1E9E000 + k*0x40000`；简体中文池位于 k=4 块内（`+0x15244`），块尾 `0x1FDE000`。
  同一固件里其它语言（日/英/德/法/西/繁/韩/泰/俄/阿…）各占一块，块首 `+0x274` 起是二改插入的本地化短文本。

实测（`tools/ui_patch.py`）：

```
CN pool : 0x1FB3244..0x1FC05FC (54,200 B)
free FF padding to block end 0x1FDE000: 121,348 B
```

## 2. 超长修改怎么做

### 2.1 后移（splice）

对要加长的记录：

1. 新记录字节 = `UTF-16LE(new)` + `00 00`，并用 `(旧长度-新长度) mod 4` 个 `00` 补齐，保持后续记录的 4 字节对齐类别不变；
2. 把 `[记录结束, 池尾哨兵)` 的整段尾部右移 delta 字节；
3. 在记录原位置写入新记录（记录起始偏移不变，后续记录后移）；
4. 池尾哨兵自动右移 `+delta`，未用的填充保持 `FF`；
5. 重算主校验和（`0x20C`），其余校验和/段头/压缩流尺寸都不变。

因为都是在**明文区**覆盖 FF 填充，所以**文件尺寸、段布局、FFLZ 压缩流长度全部不变**。

### 2.2 指针同步

扫描所有可能的绝对指针（u32 = 被移位记录的旧偏移）：

| 位置 | 处理方式 |
|---|---|
| 明文区 `[0x274, 0x260274)` | 直接改 u32（记录位置本身也可能因后移而移动，工具一并换算） |
| 解压段 sec0..sec3 | 用 FFLZ provenance 找到该 u32 的**字面量字节**并改之；打包流尺寸不变，不用重压缩 |
| 与其它数据共用字面量的字节 | 跳过并警告（该指针可能显示旧文本） |
| 运行时计算/间接寻址 | 静态扫描不到（见 §5 验证建议） |

指针候选要满足「相邻 u32 也指向本池」的启发式，避免把 u16 表格误判成指针（例如 `0x01FC01FC` 这种巧合）。

## 3. 工具用法

### 3.1 命令行（推荐：会同时修正压缩段内指针）

```powershell
# 普通修改（槽位内）
& python tools\ui_patch.py --patch mypatch.json out\patched.DAT

# 含超长修改：加 --long
& python tools\ui_patch.py --patch mypatch.json out\patched.DAT --long

# 演示（含一条超长）
& python tools\ui_patch.py --demo out\demo_long.DAT --long
```

`mypatch.json`：

```json
[{"offset":"0x1FB3254","old":"传感器清洁","new":"传感器清洁（加长说明：这是超过槽位长度的替换文本）"}]
```

超长时输出会包含：

```
0x01FB3254 OK long: '传感器清洁' -> '传感器清洁（加长说明…）' (+40 B, tail shifted)
         rewrote N section literal byte(s) through FFLZ provenance (M refs)
         pool: 0x1FB3244..0x1FC0624 (grew by 40 B, free 121308 B left in block)
```

### 3.2 网页工具

`web/index.html` / 单文件版：直接输入超长文本即可，状态列显示「已修改（超长→移位）」，
生成时自动后移文本池并修正**明文区**指针；压缩段内指针浏览器无法解码，日志会提示
「若个别菜单显示旧文本，请改用 tools/ui_patch.py 生成补丁」。

## 5. 风险与上机建议

1. **顺序假设**：多数记录没有指针，推断 UI 按顺序/索引解析池；若某版本固件实际用未知偏移表，
   后移会让该表之后的文本错位。首次请只改 1–3 条并确认显示正常。
2. **压缩段指针**：网页版不检查；CLI 版会修，但共用字面量的少数指针会跳过（有 WARN）。
3. **字形限制不变**：超长文本仍只能用池内已出现字符（见 07 §5），否则显示空白/方框。
4. **预算**：池后仅 ~121 KB；批量长文本前先看 `--list` 输出的剩余空间。
5. 保留官方固件与原始二改固件用于回退；若 UI 出现错位，优先回退而不是继续叠加修改。
