## 0. 一分钟版

1. **F-Log2 是"曝光标定 + 模式资格 + 曲线载荷"一起变**：曲线/矩阵/尾参数只是最后一层，前面还有
   手动 ISO 最低值、模式偏移、两处辅助曝光修正、配置里的模式标志（§1）。
2. **XM5 原生实现不是"最低 ISO1250 + 所有模式偏移改 300"**：ISO 控制与曝光目标分开处理，保留 raw0 身份，
   历史结果携带自己的资格，后级再按动态上限拆分并依状态选普通/Log 两份残余（§2）。
3. **XT4 侧已有实机成果**：曲线载荷 + ISO 准入在 2026-10-24 合并候选上生效（斑马线过曝位 100→85、
   低于 1250 时黄色 1250 纠正显示）；`2d1711cb` 被用户反馈"完美了"，但**只对应所测场景**（§3）。
4. **Auto 实际增益仍是最大缺口**：多个包出现"显示 A1250、实际亮度仍约 ISO640"或"显示 640 稍后 1250、
   亮度不变"的实机失败。**显示 1250 ≠ 实际增益**（§3.4）。
5. **旧"全局 300"方案已被证伪为不充分**：它改的是不同软件坐标，并在实时/历史/保存配置之间引入了
   不同的模式权威来源（§3.3、§4 第 1 条）。
6. **不要只改显示、不要只复制 300、不要把 E/F 叫模拟/数字 ISO、不要浮点重写精确整数式**（§4）；关键未闭合
   点只有五条，已从"再找几个 ISO 参数"收窄为具体对象（§5）。

## 1. 为什么 F-Log2 不是"换一条曲线"

录制配置可以理解成三块必须配套的东西：

```text
相机决定曝光（ISO 范围 / 模式偏移 / 曝光目标 / 辅助修正 / 配置标志）
   ↓
把图像编码成 F-Log2（10 字节配置 + 31 点曲线 + 3×3 矩阵 + 5 项尾参数）
   ↓
告诉预览/后期如何解释（显示辅助、文件色彩标签、直方图/斑马线）
```

只换编码曲线、保留旧曝光标定，画面会变，但不能据此认为得到了与新机相配的 F-Log2。下面是离线候选实际
采用的 A–E 五项配套（以 `xt4-codex/analysis/gamma_research/首次烧录前修改审查.md` 为准；早期是 26 跳转
方案，2026-10-24 合并为"ISO 原表 64 字节"方案，合并容器 SHA `06007b81…`）。

### A. 手动 ISO 最低值改为 1250

- 改的是**"这个模式允许选什么 ISO"的规则**，不是把全相机 ISO640 改名 1250，也不是改全局数字换算；
  目标数字范围 1250–12800，Auto 与特殊表示保留各自语义。
- 本机可复用原转换器：**X-T4 的 1250 用设置枚举 22、内部控制 867**；X-M5 的 1250 用枚举 23，编号不能跨机搬。
- 早期 26 跳转方案：入口 `0x1025d30 → 0x1e0f040`（私有规则放 image6）。2026-10-19 找到原表方案后改为
  **只改 image5 里 37 个 u32 中的 64 字节**（原表 3/4/5 行 + 参考表项 18），**指令零改动**，因此删掉了唯一的
  跨模块跳转（首烧审查 §7.1 的启动时序风险被结构性消除）。
- 结果：普通录像条件下 640/800/1000 变为 1250；保留原优先级后，仍有 180 组早期通用规则、96 组
  ISO50/102400 输入不符合旧私有夹限——**未被藏成"全部等价"**。

### B. 模式曝光标定从 200 换为 300

- 这是**固件内部的曝光标定量**，不能当成 ISO200 / ISO300。配套关系（【强】）：

  ```text
  旧 F-Log 最低 ISO640：  内部 767 − 模式偏移 200 = 567
  新策略 最低 ISO1250：  内部 867 − 模式偏移 300 = 567
  ```

  原状态重构器也能把基础 567 加回 200/300，分别还原成 640/1250。这支持"最低标称 ISO 与模式偏移一起变"，
  **不证明 567 是传感器物理原生 ISO**，也不保证最终传感器增益相同。
- 不能只改"首次进入录像"的一处：公共曝光、配置快照、录像准备、录制中重算都要读到同一策略（合并候选里
  共 19 处模式偏移调用，含 11 处录像模式调用与 8 处公共/快照/外层重算）。通用参数 `4946` **不全局改 30**，
  它仍服务其他需要一般偏移的状态。

### C. 两处辅助曝光修正改为目标模式的零默认

- X-M5 的 F-Log2 除模式偏移外，还用六个独立辅助参数，候选发布默认**全为 0**；X-T4 原 F-Log 路径的部分
  循环索引会带入 **−7 / −15 / −30** 的内部修正。
- 改点：`0x2364954`、`0x236497c`，分别进入两个 28 字节适配器（目标模式返回 0，其他模式尾调用原 helper）。
- 原配置生产函数实际写 `P28=3`（此前 `P28=1` 只跑默认 index0，故未暴露差异）。补测三通道后第一 helper 由
  `[0,−7,−15]` 变 `[0,0,0]`，完整构建输出随之改变（192 组局部比较；完整输出共 38 个半字位置变化）。
- 数值不能命名为 RGB 通道、曝光档数或最终 ISO。

### D. 模式跟随"本次配置"，而不是实时菜单

- 相机可能一边保留前次录像配置、一边切换菜单；消费旧配置时**不能临时查询当前菜单**来决定曝光。
- 做法：由原 getter 识别目标模式，在 `0x2322a64` 写配置 `P+0x91` 一字节（P91），随原复制及局部副本传递；
  识别条件含原 gate、enable 和输出 F-Log 状态，不是"菜单显示 F-Log 就无条件覆盖所有支路"。
- 生命周期只做**有限审计**：一个完整生产函数 `0x232262c..0x2322f14`（570 条指令、三个直接调用点，
  P91 无直接读写重叠）已核；后续配置复制、恢复、消费者、并发与 DMA 尚未排除。

### E. 曲线、矩阵、尾参数一起改

| 载荷 | 内容 | 改点（早期方案） |
|---|---|---|
| 主曲线 | key30：10 字节配置 `[4,4,4,4,5,5,6,6,7,7]` + 31 个小端 u16 点值 | `0x208cd1c` |
| 矩阵 | 9 系数 `938,−46,132; −25,1209,−160; 31,−333,1326`（有符号 13 bit 解释） | `0x208c1d0` |
| 尾参数 | 5 项 `[0,0,0,0,13965]`（末项与曲线末点相同） | `0x208ce74` |

- 私有载荷共 162 字节（normal 72 + 保留的特殊表 72 + 矩阵 18），存放于 `0x1e0ff40` 起。
- 曲线记录是 **76 字节**：u32 key + 10 字节配置 + 31×u16；配置描述 31 个节点的相对坐标（每项 cfg 对应三段、
  间距按 `2^cfg`，总和 1536）。**配置必须与点值一起移植**，只换 31 个数会在错误位置应用。
- 特殊条件 key10 两机相同，**不应一律强制换成 key30**；特殊覆盖、矩阵 gate/缩放分支保留原行为。
- 实机佐证（10-24）：F-Log 顶点 16383=100%，F-Log2 key30 顶点 13965≈85.2%，刷入后斑马线过曝提示
  从 100% 变 85%，与原生 F-Log2 的过曝工作流一致。

### 有依据保留的部分（不是"没改"）

| 保留项 | 原因与准确范围 |
|---|---|
| X-T4 数字 ISO 转换器 | 本机能表达 1250，用本机枚举与内部标度，不搬新机编号 |
| X-T4 原曝光求解框架 | 有界新旧对应与完整求解对照支持复用，不是已证全部 AE 状态相同 |
| 增益的分配、动态上限、限幅 | 新模式改变输入策略；不另乘 2，不把总量的一部分误当最终 ISO |
| 下游 `0x2097f84` 的 200 分割限额 | 那是"如何分配控制量"的限额，职责不同于模式偏移；不能见 200 就改 300 |
| Auto 的 raw0、基础设置与一般参考 | 0 表示自动来源，不强写 867；基础量不是可直接替换成 1250 的最终下限 |
| 本机传感器/镜头校准、黑电平、驱动 | 保留本机数据；没有搬入新型号校准 |

### 暂未适配（不要误认为"无需修改"）

| 项目 | 状态 | 首次实验如何解释 |
|---|---|---|
| Auto 实际最低 1250 | 原自动来源保留，无最终下限证明 | 先用手动 1250 核查，Auto 另测 |
| Gamma 显示辅助 | 有两组数据替换实验，未并入 | 先关闭辅助，避免旧 F-Log 映射误导曝光判断 |
| 文件/编码色彩标签 | 有独立局部原型，未并入 | 后期手动指定解释 |
| 直方图与斑马纹 | 取样位置/阈值配合未确认 | 不能把原阈值直接当 F-Log2 正确中灰/高光界 |
| SD / HDMI / 预览分路 | 部分对象与分路已找到，未闭合 | 先限定内录；不承诺混合输出独立正确 |
| 片门全开、新胶片模拟 | 不在本候选 | 不以这些作为验收项 |

## 2. XM5 原生模型：ISO 控制与曝光目标是两条线

本节提炼自 `xt4-codex/analysis/xm5_native_exposure_20261028/原生实现结论与复现规格.md`。价值不在
"新机数字是多少"，而在**哪些量必须各自配套**。

### 2.1 ISO 准入：有优先级的规则，不是无条件 clamp

- 原设置准入使用**有优先级的规则表**。在明确的一组快照下，原规则把 ISO640 提升到 1250；但另一些快照值会
  先命中更早的规则——例如 `0x9dc` 快照行 0/1 时，F-Log2 输入 80..800 一次调用先返回 1000，输入 1000 时才
  返回 1250。所以：**"F-Log2 最低 1250"是一组快照下的结论，不能抄成一行无条件规则。**
- 相关字段：`0x9dc` 快照行 → 快照 `+0x1a4`；模式组合编号（2/2→UI 5、曝光组合 2/2→4）是不同对象/不同表的
  编号，`raw2`、`UI5`、`曝光4` 必须各按所属对象使用。
- 9dc 的产品名称、完整 UI 可达性仍未证明；不能宣传"真机 F-Log2 支持 ISO1000"，也不能断言任意快照自动变 1250。

### 2.2 导入转换与 raw 身份

- 原 ISO 转换器**不按 Log 模式改变同一 ISO 的导入结果**：本轮候选参数下 **640→767、1250→867、2500→967**。
  模式资格与模式偏移 O 由另一条链产生。
- 另建的中间结构（`348a174`）在已测分支中：`Ref=567、Floor=467`，`工作控制=max(raw!=0?raw:Ref, Floor)`，
  原 raw 保留，`raw0标记=(raw==0)`。三项**不能用一个 867 替代**：raw0 时工作控制是 567、原 raw 仍 0、标记仍 1。
- Auto 基础 wrapper 另有无条件读存储 base 与动态钳制两支；把 1/1 改成 2/2 的 64 例配对结果不变。原 wrapper
  在这组输入里**没有**模式专属 `max 867`。这不排除其他设置/AE 路径构成 Auto 最低约束——"最终现象可能有
  1250 下限"与"每个内部 getter 必须返回 867"不是同一要求。

### 2.3 prepare：raw0 与固定 ISO 走不同路径

目标先归一化：`N = s16(preparedControl − capturedB − convert(referenceEnum))`，本轮普通目标源为 `N+F24`。

| 分支 | 控制侧 | 目标侧 | 身份 |
|---|---|---|---|
| 原 raw 非零 | 减 O，依原条件再限 Floor | 不额外加 O | 保留非零 raw |
| 原 raw 为 0 | 保留 Ref 工作控制 | 主/备用目标副本加 O，保存 extra=O | 保留 raw0 标记 |

相同诊断输入（F22/F24/F26=45/70/90、参考 0、capturedB 0、相同校准）下：

| 模式/输入 | raw 控制 | O | solver 边界 S0 | solver 边界 S3e |
|---|---:|---:|---:|---:|
| F-Log 固定 640 | 767 | 200 | 567 | 818 |
| F-Log raw0 | 0 | 200 | 567 | 818 |
| F-Log 固定 1250 | 867 | 200 | 667 | 918 |
| F-Log2 固定 1250 | 867 | 300 | 567 | 918 |
| F-Log2 raw0 | 0 | 300 | 567 | 918 |
| F-Log2 固定 2500 | 967 | 300 | 667 | 1018 |

两组 raw0 与对应固定基准的**完整 prepare 输出逐字节相等**——比只验证 `867−300=567` 强得多。但原配置里
raw 身份仍不同，尚不说明所有 Auto 场景最终 ISO 都是 1250。

更关键：**Q 相同 ≠ 完整求解结果相同**。沿真实 caller 连续执行 importer/solver/serializer 后发现，raw0 分支
会在 solver 内读取并更新未绑定状态 `S+dc`，serializer 再把它搬到 `row+6a`。用 `0x5a`/`0xa5` 双初值可确认：
固定 ISO 路径的 solver 实际写出**不依赖**该初值，raw0 路径**依赖**它。这是**研究 fixture 的来源缺口**，
不是证明原厂固件有未初始化错误；**不能给 `S+dc` 补零就宣称闭合**。

### 2.4 历史状态携带自己的资格

- 原实现把资格随结果发布到历史记录；恢复历史时两处 O 选择都读**同一历史对象**。当前 O300 与历史 O200
  可以合法同时存在，反向亦然。数值链（原条件成立时）：

  ```text
  E = s16(历史控制C − 历史O)
  D = s16(历史B − E)
  S = s16(历史A − D + 原校准K − 历史修正)
  ```

  声明 A700/B1000/修正 30、K 返回 0 时：

  | 配对 | E | D | writer 两份 S | 独立保存 O |
  |---|---:|---:|---:|---:|
  | F-Log C767/O200 | 567 | 433 | 237/237 | 200 |
  | F-Log2 C867/O300 | 567 | 433 | 237/237 | 300 |
  | F-Log C867/O200 | 667 | 333 | 337/337 | 200 |
  | F-Log2 C767/O300 | 467 | 533 | 137/137 | 300 |

  前两行**组合 S 相同，但 O 并未丢掉**。后续 frame callback 片段把 S 放 `payload+98`、参考转换放 `+b0`、
  `O−Z` 放 `+b8`。所以"组合 S 相同"不意味后续所有数据相同。
- 结论：**某个控制量的模式资格、有效参数选择、坐标变换与回写必须与它的来源兼容**；不是所有 reader 永远
  返回 300，也不是加一个历史 flag 就自动正确。

### 2.5 后级：动态 cap 拆分 + ordinary/log 两份残余 + 状态 gate

- 七个上游量 A/J/B/C/D/E/F 是**源字段标记**，不能凭位置命名为模拟 ISO 或数字 ISO。100 例原码执行中，
  E/F 确能由原生产者算出不同（P0=100/P1=0 → E=100/F=0；P0=79/P1=0 → E=0/F=79）。
- 动态 cap 由原 `337f3f8` 以 C 与参考参数计算，诊断输入下近似 `100*log2((4095−C)/(4095−reference))`，
  **精确结果由原整数表和舍入给出**。直观关系（**只是解释式**）：

  ```text
  请求项 = A+J+B−D−E          （原条件先决定是否置 0）
  split = 按 cap 拆分的部分；excess = 超出 cap 的部分
  ordinary = E + excess；log = F + excess
  ```

  **精确实现含 s16/u16/low16 与符号不同的指数转换，移植不能直接换成无边界浮点式。**
- 完整 builder 依状态 gate 选 ordinary 或 log，再构建描述符，consumer 把 8 项追加到原 IO 队列。同一输入
  分别跑 F-Log/F-Log2，两个模式的全部 8 项队列值相同——**末级没有模式专属的无条件 +100/+300**；差别只能
  来自上游输入、动态 cap 与状态选择。
- 状态换源既可能增加、也可能减少第二项增益（与用户"亮度来回变化"的现象相符），但**尚未证明真实半按切
  这个 gate**；`record+4550` 由原 setter 写入、两处初始化分别置 0/1，**不能把 gate 字段命名为半按开关**。

## 3. X-T4 候选演进与实机状态

候选包目录名里的短 SHA 即产物/基底标识。状态以各包目录里的最新状态文件为准。

### 3.1 `427b77a7`：相对直接基底只新增 11 处

`xt4-codex/analysis/firmware_package_audit_20261028/auto1250_427b77a7/改动说明.md` 用独立 LZ 解码器直接
核对四份实际 DAT：

- 相对直接基底 `0dd0b1d6`：**只有 11 处声明修改，全在 image6**——原零区 `0x1e0f6a8..0x1e0f6eb` 新增
  **68 字节** ARM 函数，**10 处**原本直接调 `0x12fd1d0`（本机原 Auto 基础 getter）的 BL 改调新函数。
  实际不同字节 **83** 个（108 是声明覆盖长度，不是逐字节差异数）。
- 新函数逻辑：`base=原getter(context)`；`raw=原rawISO getter(context)`；`raw==0` 且目标模式资格谓词==1 时
  返回 `signed_max(base,867)`，否则返回 base。867 是既有转换器中 ISO1250 对应的内部控制量，不是把 ISO
  字段直接写成 1250。
- 10 个调用点：`0x22e5784 0x2302bc8 0x232872c 0x2351edc 0x235dfa0 0x23675a4 0x2369b14 0x236b16c 0x236cff0 0x236d670`；
  image1/image5/image7 与基底完整一致，除 image6 压缩槽及 DAT `0x20c..0x20d` 两个校验字段外全部一致，七个范围校验通过。
- **相对原厂还继承**：双胶片（SEPIA→Nostalgic Neg.、普通 Monochrome→REALA ACE）、F-Log2 图像处理载荷
  （key30 主曲线、key10 特殊曲线、3×3 矩阵、尾参数）、既有 ISO 规则与模式资格、两处辅助 0 修正；**旧 32 处
  300 偏移调用已恢复本机原函数**（32 个目标指令与原厂逐字节相同，选择器 `22ac5f0/22ac624` 区间也等于原厂）。
- 实机反馈：**相对正常**（仅该对照语境），不能据此证明已等价 XM5，也没有证据要求立刻恢复全局 300。

### 3.4 "显示 1250 ≠ 实际增益"

- `6a085b21`：实机仍显示 ISO A1250，但实际亮度/增益看起来仍约 ISO640。
- `cb1e0a93`：A640 稍后显示 A1250，仍比手动 1250 暗约一档；且它是对 `6a` 的无效重复（此前的
  `[667,567,100]` 是误认，`6a` 本身输出已是 `[667,667,0]`）。
- `43098c17`：显示从 640 变 1250，亮度不变；手动 1250 明显更亮。
- 教训：**ISO 显示、菜单/规则限制、实际增益是三个层次**；只改显示或规则表可能屏幕正确、画面错误。反过来 `a2139129` 证明"实际增益对了、显示没同步"也会被当成没修好，`7719fcc3` 是在已生效的实时增益上同步另一条结果路径，不是重新修 6a。

## 4. 已纠正的错误模型

1. **不能只复制 300。** 旧 300 适配改变的是不同软件坐标：固定非零控制下准备器 Q24 由 `867/767/667` 变
   `567/567/567`；raw0 下 Q1e 由 `500/600/700` 变 `800/800/800`。且旧方案在实时/历史/保存配置之间引入了
   不同的模式权威来源（保存配置读 P91，实时路径查当前 context），两源故意不一致的 6 例全部分叉，可能留下
   `O_current − O_saved` 残差。**这是软件敏感机制，不是已复现的真机故障。**
2. **不能只改显示。** 见 §3.4；另核实预览链的 EV→百分数接口单位必须严格保持（`−100→50`、`−33→80`、
   `0→100`、`33→126`、`100→200`），零控制量=100%、返回值 0=0% 并不等价。
3. **不能把 E/F 当模拟/数字 ISO。** A/J/B/C/D/E/F 是源字段标记；E/F 是两份可由原生产者算出不同的基量；
   两个描述符位置也不能强行命名为"传感器模拟增益 / ISP 数字增益"。
4. **cap 跨界分配是连续的，不是截断。** `kept=min(T,C)`、`extra=max(T−C,0)`、`kept+extra=T`；实际案例
   1297 在 cap 896 下分成 896/401，401 转入另一控制项、没有丢失。只改其中一份量必错。
5. **frame callback 的 `+98/+b0/+b8` 与 gate 各自身份不同。** `+98=S`、`+b0=参考转换`、`+b8=O−Z`；`+98`
   与 `+b8` 不是同一来源，组合 S 相同不意味后续相同。gate 有配置先行分支与 state 枚举过滤，初始化路径出现
   0/1 **不证明**每次半按都会切换。
6. **历史 ring 基址已更正：`5831530 → 5836530`。** 旧资料里的绝对地址错误，但该文档错误**本身不构成**
   旧 XT4 故障的因果证据。另：中间节点相同（如 S0 都是 567）≠ AE/增益适配；合成 RAM 输出一致 ≠ 整机等价。

## 5. 证据分级与未闭合边界

### 5.1 四类来源能证明什么

| 来源 | 典型产物 | 能证明 | 不能证明 |
|---|---|---|---|
| 静态 | REA/Rizin 原字节、反汇编、参数表提取 | 指令/表内容、调用关系、字节归属 | 运行时取值、可达性、硬件效果 |
| 受控原生执行 | Unicorn 跑原指令、双初值、双栈填充 | 声明输入下的完整输出 | 真实任务/并发/整机时序 |
| 离线包检查 | 解包/重压回环、七校验、回读 SHA、独立审计 | 文件可承载且自洽、改动范围 | 更新器接受、开机、恢复、像素 |
| 实机反馈 | 用户报告 + 状态文件 | 该包在该场景的现象 | 其他场景、其他设置、全部路径 |

**七校验**即 [FIRMWARE-STRUCTURE.md](../FIRMWARE-STRUCTURE.md) §6：主校验和 + R0..R5，
`checksum = 0xFFFFFFFF − Σ(bytes)`；其中 R2/R3 两段按**存储字节**求和。任何改包都要重算并回读。

### 5.2 仍未闭合的五条（按重要性）

1. **`S+dc` 的真实来源**：raw0 solver 会读它、serializer 写 `row+6a`；来源与整 row 生产未恢复，所以 prepare 配对还不能推到完整 Auto 输出（不能补零冒充闭合）。
2. **solver 输出 → 最终 gain SOURCE**：E/F 已闭合一条真实包生产路径的双路选择与导入，但另一索引池路径的 copy 生产与完整事件来源仍未闭合。
3. **frame callback → gain 输入**：`+98/+b0/+b8` 如何送到这些 SOURCE、真实半按/AE 锁定究竟改变哪份来源和哪个 gate，仍未证明。
4. **真实半按事件**：只有 handler 表/分派器/wrapper 的静态接通（事件索引与 handler 表已定位），**消息名/索引是否就是物理半按/释放未证明**，也无从启动到编码的完整运行记录。
5. **XT4 与 XM5 坐标是否一致**：必须由 XT4 原码与失败包差分闭合，**不能按 XM5 地址直接套补丁**。

另有一条工程性边界：**原 DAT 候选参数 bank ≠ 相机活动 bank**。原初始化包含多条来源（flash 块读取、超出
更新范围的存储区、从运行地址整体复制），没有相机存储 dump 就不能把发布载体值当成"当时真机是多少"。

## 6. 对 X-T4 读者的可操作结论

### 6.1 要动哪几层（按"最小可解释"排序）

1. **数据层优先**：ISO 规则表（image5 的 64 字节）、曲线/矩阵/尾参数载荷、辅助表零默认。这类改动可做到
   零指令或极少指令，便于独立审计与回退。
2. **准备层**：模式偏移 O、目标归一化、raw0/固定 ISO 分支。必须确认改动**只作用于本次配置**（P91 或等价
   资格），不能全局改共享选择器。
3. **后级**：动态 cap、ordinary/log 两份残余、状态 gate。**没有真实 gain 链路证据前不要动**；只改其中一份量
   会在状态换源时失配。**显示/标签层**是独立支路，最后做，不能替代曝光/增益验证。

### 6.2 最低验证清单（离线到实机）

- **完整 prepare / solver 输出**：不能只比 S0 或某一中间量；要比整段 0x44 字节 prepare 输出、solver 实际
  写出、serializer 行。已知反例：S0 同为 567 时 S3e 可差 100。
- **双初值**：用 `0x5a`/`0xa5` 填充未声明栈区，确认结果是否依赖未绑定状态（这正是发现 `S+dc` 的方法）。
- **非目标路径回归**：普通模式、HLG、手动 ISO、固定控制、非目标 channel 的完整输出必须逐字节不变。
- **包级检查**：4 个映像独立解包、声明改动范围、七校验、回读 SHA；记录"相对基底的差异字节数"。
- **实机半按序列观测**：稳定预览 → 半按瞬间 → 持续半按 → 释放 → 恢复稳定；分别在固定 ISO、Auto 触底、
  Auto 高于下限、不同曝光模式/AE 锁定下记录：raw 身份、当前/历史资格与 O、captured/reference、prepare
  目标、solver 结果、E/F 两份来源、gate 与最终队列值及帧归属。先确定"最早改变的是哪一层"，才能区分策略本意、坐标失配与跨帧拼接。

### 6.3 不要做什么

- 不要把通用参数 `4946` 全局改成 30，也不要把所有 F-Log 偏移固定成 200 或 300；不要只改 ISO 显示数字/菜单，也不要把"显示 1250"当增益证据。
- 不要强制 bank 提交 flag=1（flag0 有独立回调），不要给硬件增益寄存器固定 +100 或 ×2。
- 不要给 `S+dc` 补零后宣称闭环，不要把精确整数式重写成无边界浮点式。
- 不要整块搬 X-M5 的对象布局、队列或驱动；不要按 X-M5 地址直接给 X-T4 打补丁，也不要把一次"完美了"外推到全部场景。
- 不要覆盖旧 DAT，回退包要单独留。
