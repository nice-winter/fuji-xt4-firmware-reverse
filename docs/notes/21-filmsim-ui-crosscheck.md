## 2. 三层结构：已发表结论与独立互证

### 2.1 名字表层

* 本仓库 note 11：sec0 `0x407934` 的 `MODE_FSIM_*` 名字块，**19 个有效值** + 末尾 `MODE_FSIM_NUM`；滤镜（`MONO_*`、`ACROS_*`）是**独立值**；名字表没有被 u32 指针引用，按下标取。
* 快照侧 `phase1_enum_mapping.md`：设置枚举名函数（image5 `0x102df5c` 一族）按 `cmp #0x14` 逐项返回字符串，末尾返回 `MODE_FSIM_NUM`；该函数只服务日志/调试。
* **交叉核对**：两者描述的是**不同编号域**（sec0 的 19 个调试名 + NUM vs 设置枚举 0..20 共 21 个值，X-M5 为 23 个），不要互相“修正”；共同结论是“**名字序不等于菜单序**，名字表只是显示/日志用途”。

### 2.2 UI 名字与注册表层

* 本仓库 note 09/11：sec1 `(name_ptr, index)` 8 字节注册表 `0x6C8150..0x6D8AA0`，index 从 0 起 ⇒ **index = 枚举值**；`UI_FILM_SIM_*` 23 项表在 sec1 `0x6D35F8`。
* 快照侧：同一族 UI 名字资源在 image2/image5 侧也有一份索引结构（`0x24e25f8` 一族被定性为“UI 自动化 ID 表”，不是可见菜单），并指出 **`UI_SETP_FILM_SIM = 0x42e`** 的设置注册表在 img6。
* **交叉核对**：两边的“设置 ID → SETP 记录 → 选项表”链在本仓库 note 13 §3.5 与快照侧 `MENU_FEASIBILITY` 中**逐项对得上**（1070/1071/1072/1073/1076 与 12 项表/子表）。

### 2.3 显示文本层

* 本仓库 note 11/14/16：FDL 文本池里的选项标签是**复合串**（`\uf2fa\uf2ef+G FILTER`、`\uf3e5ETERNA BLEACH BYPASS`），行首 PUA 是内嵌图标/子串引用；`PROVIA/Velvia/ASTIA` 没有拉丁字符串（logotype 字形）。
* 快照侧：二改在每个语言块写入 `REALA ACE` / `NOSTALGIC Neg.` 与描述、PUA 标签，并改 8 字节消息记录的 `text_off`；每块 24–28 处、35 块合计 884 处。
* **交叉核对**：两处独立统计的“每块改动形态”一致（新增文本 + 消息记录指针重指），可放心把“二改是换皮而非新增条目”当作已发表结论。

### 2.4 编号域警告（最容易出错的地方）

同一组数字在不同表里含义不同，至少存在六套域：

| 域 | 载体 | 例子 |
|---|---|---|
| UI / 设置值 | 换算表 col0、SETP 选项表 | `5` = SEPIA，`7` = BW 家族父值，`8..11` = 黑白 NON/R/Ye/G |
| 换算表其他列 | img5 `0x14c2bb0` 每行 4×u32 | col1 = 第三个小枚举族；col2 = 开发 enum；col3 = compact 显影码 |
| compact 显影码 | `dev+0x21d` | 1..18 为现有模拟；X-T4 只用到 1..18 |
| producer 内部 enum | `0x2098ac8` 入参 | 1..20；**19/20 在这一域是 NC/漂白** |
| class / column | `ctx+0x5a`、`0x12e2f0c` | class 0..15、column 0..17 |
| 曲线 key / 矩阵 idx | 曲线库 `0x170ac14`、矩阵库 | key 0..26、idx 0..18 |

**19/20 的措辞演进必须交代**：phase1 阶段称“空座位”（compact 码 19/20 在 X-T4 无人使用，跳表槽已接到 class 10/11、曲线 key19/25、矩阵 12/13）；后期 `chain_closure/README.md`、`故障排查进展_交接.md`、`交接_给GPT.md §11` 明确纠正：**同一个 19/20 在 producer 内部 enum 域是 NC/漂白，只有 compact 码域才“空”**。引用时写清域，否则会出现“新模拟占用 19/20”与“19/20 已被占用”的表面矛盾。

另外，本仓库 note 12 的“BW 滤镜 enum 8/9/10/11、ACROS 19/20/21/22”是 **`UI_FILM_SIM_*` 注册表枚举**，既不是 compact 码也不是 producer enum——与快照侧“新模拟用 19/20”不是同一件事。

## 3. 枚举顺序 ≠ 菜单顺序：两边合起来才闭环

### 3.1 本仓库已排除的假设（不要重复劳动）

note 11 §3 已逐项否定：13/14 项 `0..N` 排列表、u16 消息 ID 顺序数组、u32 指针表、官方 vs 二改差异、文本池顺序。note 12 §7.3 又否定了 23 项家族数组、mono flag 数组、家族 bitmask、SETP 值列表。结论：**顺序/家族判定不在这些数据形态里**。

### 3.2 快照侧补齐的数据链

* 菜单是**两层 SETP**：`SETP 1070` 的 12 项表 `{u32 值, u32 子 SETP 记录}`，只有 `value=18`（ACROS）与 `value=7`（黑白家族父值）带子记录；子记录的值表就是右列 `19,21,20,22` / `8,10,9,11`。这与本仓库 note 13 §3.1–3.2 完全一致（快照侧用的是 image5 文件偏移，本仓库用 sec0 偏移，同一批数据）。
* 另有 **5 份 18 项平坦表**（`0,3,1,14,13,12,15,16,17,19,21,20,22,8,10,9,11,5`），Q 菜单/快捷项用它——这就是 note 15 §7 里“Q 菜单还能滚到三个滤镜”的数据来源。
* 快照侧新给出**可用性门控**：img6 胶片可用性 descriptor `0x25a5f64` 首三个 u32 为 `[18,10,0x196ba9e]`，其中可用性指针 `0x196bab0` 恰好等于 `0x196ba9e+18`；**把 count 18 原地改成 20 会越过现有数组、占用下一个数组的 2 字节**；初始化 `0x2013664` 清零 `0x196ba2c` 起 `0xdc` 字节，`0x20138d8` 按 count 迭代写可用性字节。
* 标签记录也不能一概而论：`0x1503d60` 家族的标签资源值在记录 **+16**，`0x1514078` 家族在 **+4**——扩容或改名必须逐族定位。
* 结论（`MENU_FEASIBILITY_REAUDIT`）：**真正新增两项**需要同时证明“菜单 RAM 归属 + 初始化 + 资源路径”，当前不成立；**替换现有入口**（SEPIA / 普通 Monochrome）在九个已审计菜单族中都有静态路径。

### 3.3 五层都要看：枚举 / 注册表 / 菜单 / 图标 / 文本

note 12 的实机反例（清空 BW 标签 → 界面无变化）证明了“文本层单独改无效”；快照侧“复活换算表死行 → 新项不出现”证明了“换算/枚举层单独改也无效”。**任何只改一层的方案都必须先说明另外四层为何不受影响。**

## 4. 快照侧的 NN / REALA ACE 移植路线（替换槽位）

### 4.1 目标与入口选择

用户授权的目标是：在 X-T4 上得到 NOSTALGIC Neg 与 REALA ACE，**复用 X-M5 完全相同的参数与数据**；优先新增菜单，过于困难时允许**替换 SEPIA 与普通 Monochrome**（`CONTINUATION_REAUDIT_2026-10-27.md`）。

| 路线 | 做法 | 结局 |
|---|---|---|
| 纯新增（复活死 UI 槽 + 注入 builder case + 反向 getter + 数据座位，约 280 B；候选 `7c57311f…`→修正 `00f39f42…`） | 不动现有模拟 | 【离线验证】全绿；**【实机否决】**：新项不出现 + Classic Neg 变黄。根因只到“头号假设：F-Log2 适配器门控 `ctx+0x13a==1` 被误触发”，**未闭合**，后续不再沿用 |
| 替换入口（SEPIA→NN、普通 Monochrome→RA） | 换 develop 入口与配套数据，不改枚举值、不增菜单项 | 成为后续主线，见 §4.2–§4.6 |

被替换的两个入口在快照侧换算表里是：`UI5 SEPIA = [5,4,5,10]`（col2 开发 enum 5、col3 显影码 10）、`UI8 普通黑白 = [8,3,7,6]`。黑白家族另外三个变体（`UI9/10/11`）使用不同开发 enum，**没有被一并替换**。

### 4.2 b1plus 诊断入口

在真菜单方案受阻后，先用“SEPIA → 内部测试码 21/22”的诊断入口验证出图：

| 包 | 入口 | 离线验证 | 实机 |
|---|---|---|---|
| NN 包 `d5367fb3…` | SEPIA → 内部码 21 | REA 105 记录/1622 解码项/1597 指令匹配；builder 23/23；bridge 18/18；五路分流；封包校验 | 未见正式相机记录 |
| Reala 包 `232ff2ff…` | SEPIA → 内部码 22 | 同上 | 未见正式相机记录 |

边界（原文）：这是**最终测试固件而非自然菜单版**；入口仍是诊断映射；marker 是**单线程诊断选择器**，未宣称并发混合显影安全。

### 4.3 “真菜单 vs 诊断入口”的评估结论

`MENU_FEASIBILITY_REAUDIT.md`：SEPIA→developer5、普通 Monochrome→developer7 在九族菜单里都有静态路径；**真正新增两项尚缺**换算域、列表、资源文字、可用性与输入传播五件套；可用性数组扩容会越界（§3.2）。因此按用户授权继续替换路线，并明确“该选择解决真实可选入口，不解决 context 身份、第二层影调与成像选择链”。

### 4.4 双模拟完整实现（替换方案）

* **第一层已完全一致**（`NN_RA_EXACTNESS_AND_PLAN.md`）：31 点 RGB 曲线 15/15 槽位、矩阵 9/9、C 小表 4/4、AB 小表 4×u8 + 10×u16 全等于 X-M5。
* **第二层影调**：XM5 的 NN 用档位 17–20、Reala 用 22–25，级联到子表 99..122、曲线 id 91..95/169..255；合计 **150 条记录 / 116 个唯一 40 点曲线体 / 约 9.3 KB**，XT4 现有库里**一条都没有**且不可近似（最近邻 max|Δ| 4510，range 仅 ~9000）。
* **存储**：曲线库连续排布、尾部接计数表，原地扩不了；`xt4_packer` 不允许改变解码大小。唯一够大的连续空洞是 **img7 `0x4330cb0..0x4335320`（约 18 KB）**，但位于 MMU attr-11 段、被活描述符数组夹着，**静态无法证实运行时可写且不被占用**。因此 B1+ 阶段不搬专属影调，新模拟继承所选影子类（class 10）的影调；要补专属影调必须走该空洞并先在运行期验证。
* **B2 曲线加载**：在原库区域（约 46,620 B）内做**双命名空间去重**——stock 555 条 + donor 705 条按 80 字节曲线体去重为 **508 条**，加 4096 B 双命名空间索引；调用链必须携带命名空间，不能把高位塞进 8 位曲线 ID。
* **context 身份**：`ctx+0x56` 是**在用字段**（有写入、消费与重叠字读取），不得占用；候选为 **`ctx+0x75`**（context 实际分配/复制长度 `0x314`，7 个 slot 间距 `0x314`）。全局 marker 方案已被证明会跨 context 覆盖，仅适合单线程诊断。
* **其它配套**：矩阵/曲线/C/AB 钩子必须**先保留 F-Log2 优先级**再判身份；`0x32d/0x32f` 是 MF split 辅助的 MONOCHROME/COLOR 选项，**不能**误改成 RA；Ye/R/G 保留是因为旧自定义预设会按枚举回落显示第 0 项，删除会造成显示与处理不一致。

### 4.5 链路闭合与剩余门槛

`chain_closure/README.md` 用完整 `0x21bae78` builder + host Unicorn 复现了 23 个 enum 的局部生产/查表与 18 个标准紧凑码逆转换，并给出 record→请求对象桥、indexed bank snapshot→capture 指针数组的复制边；但**上游存在显式声明的合成连接**（converter 参数、跳过通知门控、强制 source=CURRENT、强制 callback 输出为 SNAPSHOT），**尚未完成相机 JPEG/机内 RAW 的端到端闭环**。REA 侧累计 105 份记录 / 1622 解码项（其中 1597 计入指令匹配），全部为静态证据，不等于相机执行。

## 5. 与本仓库已实机验证补丁的关系

### 5.1 本仓库的补丁（note 15）

* 改动：SETP 1070 的 12 项表里 `value=7` 的子记录指针清零（DAT `0x4BB45C..0x4BB45F` → `FF FF FF FF`）+ movie 表同源字面量 `0x4BB606` `0x37→FF` + 主校验和重算 → **DAT 共 7 字节**、sec0 解压差异恰好 8 字节、sec1/2/3 不变。

### 5.2 与快照侧路线的层次对比

| 手段 | 改动量级 | 作用层 | 主要回归面 | 状态 |
|---|---|---|---|---|
| note 15：清子指针 | 7 B（数据） | UI 展示（SETP 值表） | 右列是否消失、REALA 是否仍彩色、ACROS/电影菜单 | 【实机验证】 |

## 6. literal vs copy 与打包约束

### 6.1 溯源工具

`tools/fflz_trace.py` 逐字节标注 sec0 解压输出是 **literal**（压缩流里的字面量，可原地改）还是 **copy**（LZ 回溯引用，改它会连带改到别的输出字节）。note 15 的 still 指针是 4 字节字面量 run，**movie 指针的低字节是独立字面量 `0xC8`，其余 3 字节是从 still 指针 copy 来的**——所以必须两处一起清，否则 movie 表留下非法指针 `0x000000C8`。

### 6.2 共享字节污染的真实案例

note 15 §7.2 记录了三次“原地改一张表、连累兄弟指针”的失败：清 bank B 1070 的 value=7 指针 → bank B 1073 的 `p2` 变成 `0x000000B8`；改 1079 的 `p2` → 1076 的 SELECT 映射表被改坏；改 flat 1070/1080 的 `p2` → 其 `p3` 消息表指针被改坏。**判据是“解压后 diff”，不是“文件里只改了 4 字节”。**

### 6.3 快照侧的打包硬门槛

`tools/packer_research/README.md` 的约束（重编码路线必须满足）：

* 输入固定为原始 `FWUP0024_XT4.DAT`（SHA `853d273b…`，51,278,280 B），其他型号/版本/已改源文件**拒绝**；
* 自写 FFLZ 编码器：滑动窗口 2047 B、贪心最长匹配、长度上限 15、等长取最近距离、无自重叠，且遵守 **0x4000 字节硬件 feed 页边界**；
* 只允许**同长度槽位替换**，保持原长度与前 32 字节；**禁止改变镜像解码大小**；
* 必须重算**七个范围校验**、磁盘副本重新提取、逐字节比较声明允许范围之外的**全部字节**；
* 输出强制限定目录 + `.not-for-camera.bin` 后缀 + 拒绝覆盖，**没有可解锁的刷写模式**。

### 6.4 对本仓库的提醒

本仓库 note 15 采用的是“**单段字面量原地改 + 只重算主校验和**”的更小路径，它在二改（只改非压缩区）之后**没有先例**，所以 note 15 明确保留了“先做等价重压缩 S1 验证”的升级路线（sec0 余量约 88 KB）。两边都应遵守同一条纪律：**先在解压层验证差异边界，再回包；回包只重算声明范围内的校验。**

## 7. FDL Font 与图标字体

### 7.1 本仓库已确证的结构（note 14/16）

* 8 个 `"FDL Font\0"` 包；#0 在 decoded `0x1DA0274`、长 `0x980000`，含共享字形区 + **35 个 0x40000 语言块**。
* 字形偏移表 `{u8 flag, u24 end_offset}`，`end_offset` 单调不减；数据区起点 `0x3DCED`；cmap 公式 **`glyph_id = 码位 − 0xE120`**（394/394 PUA 码位命中“有轮廓”字形）。
* 字形记录：`simple = {0x00FA, len, data}`；`complex = {flags, advance, n, chunks}`；`empty = {flags, advance, 0,0}`；11 个 opcode 的变长路径指令流；画布 256×256。
* **未解**：`0x92/0x96` 的点是 on-curve 还是控制点、`arg` 的语义、轮廓点序（note 16 §5.1、§10）。

### 7.2 快照侧工具可作为互证

`tools/filmsim_research/patch_film_icon_font.py` 在**字体资源块**上做原位插入：

* 目标码位 `U+F445`（REALA ACE 图标），既有 `U+F3EE`（NN 图标）在 X-T4 中**与 X-M5 donor 逐字节相同**（403 B）；
* donor 字形 477 B（SHA 前缀 `01a25388…`）；插入后表尾全部码位的 `end_offset` 平移、`+0x3a`/`+0x44` 两个 header 字段同步、字宽表 `U+F445` 由默认 **1000 → 800**；
* 能力/长度断言：字体块容量 `0xC0000`、原长 `0xA3EBD`、`info` payload 后移 `0x1DD`（与 note 16 测得的“插入 477 字节、info 后移 0x1DD”一致）；外层 image2 目录里的长度字段（文件偏移 `0x140304`）需独立更新；
* 工具自身声明：**只证明资源一致性，不证明相机端栅格化**。

### 7.3 两个“表面矛盾”的解释

1. **`U+F445` 到底空不空？** 快照侧脚本要求它**为空**（在官方 v2.12 字体块上插入），而 note 16 在**二改**里看到 `U+F445` 已被填入 REALA 图标。两者是不同映像，不矛盾；写工具时必须确认自己在哪个底包上。
2. **loca 表长/起点口径**：note 16 按“非空 PUA 段”表述为 **5638 条、起点 bundle+`0x384D4`、cmap=`码位−0xE120`**；快照侧按字体头声明读成 **`0x51` 起、`maximum+1 = 0xF727` 条整段码位表**（其断言 `table+(max+1)*4==data` 在该块上通过）。两者都落在同一数据区起点 `0x3DCED`，对“`{u8,u24}` 记录、PUA 图标、矢量轮廓”的结论一致；但**索引口径不能混用**（否则 `F445` 的偏移计算会差出一整个码位前缀）。

### 7.4 对图标/字体工作的建议

* 只想“**让新名字有图标**”：沿用 note 16 的定位（`F445/F3EE`）+ 快照侧的插入/字宽方法，注意二改已经填过 `F445`，不能重复插入；
* 想“**像素级正确渲染**”：两边都停在“几何可信、绘制语义未定”，下一步都是**反汇编渲染器**（本仓库 note 16 §9.1 / §10）；
* 35 语言说明的移植（快照侧 `PRESENTATION`）与语言文本池的编辑（本仓库 `07`、`web/FWUP语言补丁工具.html`）是**同一资源族的两端**：前者改消息记录指向，后者按池内已有字符原位改写；两者都要求重算容器校验（本仓库路径为主校验和 `0x20C`，快照侧路径为七项范围校验）。
